# Из брифа — ТЗ и прототип

Бриф одной фразой, например «нужна онлайн-запись в автосервис». Дешёвые модели по шагам разбирают бриф, пишут ТЗ по шаблону, собирают кликабельный прототип и принимают его по критериям из ТЗ. Каждое ТЗ проверяют код и вторая модель, красное уходит на доработку. Под каждым шагом видно время, токены и рубли.

**Статус на 2026-10-09.** Сервис и страница работают. Замер на 20 брифах ещё не сделан. В «Где ошибается» — проверки на 10 испорченных и 5 правильных ТЗ ([evals/runs/](evals/runs/)) и три записанных прогона ([app/recorded/](app/recorded/)).

## Кто что решает

| Шаг | Кто |
|---|---|
| скрыть телефоны и почты в брифе | код ([app/pii.py](app/pii.py)) |
| разбор брифа: чего хочет бизнес, кто работает с системой, что додумано | `gemini/gemini-3.1-flash-lite`, JSON по схеме |
| ТЗ по шаблону из 10 разделов ([docs/template.md](docs/template.md)) | `anthropic/claude-haiku-5-5`, JSON по схеме, текст собирает код |
| форма ТЗ: K1–K12 | код ([app/checks.py](app/checks.py)) |
| смысл ТЗ: Ч1–Ч8 ([docs/checklist.md](docs/checklist.md)) | `openai/gpt-4.1-mini`, модель другого семейства, чем автор ТЗ |
| доработка красного ТЗ | автор ТЗ, не больше двух кругов, потом ТЗ идёт дальше с пометкой «с замечаниями» |
| прототип одним HTML-файлом | `anthropic/claude-haiku-5-5` |
| прототип: P1–P5 (разбирается, до 80 КБ, без сети, экран на сценарий, переходы) | код |
| приёмка по критериям ТЗ | экраны и поля — код, остальное — ревьюер по тексту экранов |

На пробе flash-lite писала ТЗ с 3 критериями и прототип на 2–4 КБ, у Haiku вышло 7 критериев и прототип на 10–20 КБ ([evals/probe-models-2026-10-08.jsonl](evals/probe-models-2026-10-08.jsonl)).

## Где ошибается

- Код поймал все 5 испорченных ТЗ своего вида: сценарий без роли, расплывчатый критерий, сумма дней не сходится. На правильных ТЗ ложных тревог у кода нет.
- Смысл код не видит. Цель про систему вместо бизнеса или сценарий, которому не хватает данных, ловит только ревьюер.
- Ревьюер `gpt-4.1-mini` нашёл 1 из 5 смысловых ошибок, к правильным ТЗ не придрался ни разу.
- `claude-haiku-5-5` в роли ревьюера нашёл все 5 смысловых ошибок, но забраковал и все 5 правильных ТЗ, чаще всего за оценку в днях.
- Кто из ревьюеров ближе к живому аналитику, покажет сверка с ручными оценками ([evals/calibration.py](evals/calibration.py)).
- Прототип — макет для разговора с клиентом: данные выдуманы, кнопки только переключают экраны.
- Прогон идёт дольше минуты. Три записанных прогона заняли от 73 до 96 секунд и стоили от 1,54 до 1,96 ₽.

## Как попробовать

```bash
docker compose up -d --build                      # порт 127.0.0.1:18105
curl -s 127.0.0.1:18105/api/brief/health
curl -s -X POST 127.0.0.1:18105/api/brief/runs -H 'Content-Type: application/json' \
     -d '{"brief": "нужна онлайн-запись в автосервис"}'
curl -sN 127.0.0.1:18105/api/brief/runs/<id>/events   # ход шагов по SSE
```

Ключ и адрес шлюза Timeweb AI — переменные `LLM_API_KEY` и `LLM_BASE_URL` (в compose — файл `../llm.env`). Без ключа живой режим выключен, работают записанные примеры. Модели — `PARSE_MODEL`, `SPEC_MODEL`, `REVIEW_MODEL`, `PROTO_MODEL`. Контракт API — [docs/api.md](docs/api.md), устройство — [docs/SPEC.md](docs/SPEC.md).

Без ключа и без денег: `python3 scripts/dev_server.py --port 8765` — сервис на сценарном шлюзе.

Тесты: `pip install -r requirements-dev.txt && pytest`.

## Песочница прототипа

- Прототип открывается в `<iframe sandbox="allow-scripts">` без `allow-same-origin`: его скрипты переключают экраны, но не видят страницу, куки и хранилище.
- Сервер отдаёт прототип с CSP `sandbox allow-scripts; default-src 'none'` и только в рамку своего сайта.
- Если проверка P3 нашла в прототипе сеть, прототип не показывается.

## Лимиты и данные

- 3 прогона в час с адреса (адрес хэшируется с солью), бриф до 500 знаков, не больше 2 прогонов одновременно, прогон до 5 минут.
- Дневной бюджет 15 ₽: худший случай вызова резервируется до вызова, после — списывается факт ([app/pricing.py](app/pricing.py)). Прогон стартует, только если денег хватает на проход без повторов.
- Бриф со скрытыми контактами, версии ТЗ, замечания и прототип хранятся 30 суток.

## Структура

```
app/main.py       эндпоинты /api/brief/*, лимиты, SSE
app/pipeline.py   шаги: разбор, ТЗ, проверка, прототип, приёмка
app/checks.py     проверки кодом K1–K12, P1–P5, приёмка по экранам и полям
app/prompts.py    промпты шагов
app/schema.py     JSON-схемы ответов моделей
app/gateway.py    шлюз: chat, повтор на 429 и временных ошибках
app/store.py      SQLite: прогоны, события, расход, лимиты
app/recorded/     три записанных прогона
evals/            замер: брифы, испорченные ТЗ, проверки, калибровка
scripts/          сервер для разработки, запись прогонов
```
