# API «из брифа — ТЗ и прототип» (`/api/brief/`)

| Метод и путь | Что делает |
|---|---|
| `GET health` | жив ли сервис |
| `GET status` | `live`, бюджет на сутки и потрачено, худший случай одного прохода, сколько прогонов идёт, модели по шагам, прогонов за сутки |
| `POST runs` `{"brief"}` | новый прогон (бриф до 500 знаков, 3 в час с адреса, 2 одновременно на сервис) → `{"id"}` |
| `GET runs/{id}` | состояние прогона, см. «Состояние прогона» в [SPEC.md](SPEC.md) |
| `GET runs/{id}/events` | ход прогона по SSE; `Last-Event-ID` продолжает с места; не больше 3 потоков на прогон и 12 на сервис (иначе 429 `busy`) |
| `GET runs/{id}/prototype` | HTML прототипа в песочнице; только в рамку (`Sec-Fetch-Dest: iframe` или без заголовка), иначе 404 |
| `GET examples` | записанные прогоны: `[{"name", "title", "brief"}]` |
| `GET examples/{name}` | записанный прогон: `state` и `events` с `t_ms` для проигрывания в темпе |
| `GET examples/{name}/prototype` | его прототип, те же заголовки песочницы |

Бриф хранится с контактами, скрытыми метками (`[телефон скрыт]`), 30 суток; адресов нет.

События SSE: `id:` — номер события, `data:` — JSON. Типы: `step_start`, `step_end` (время, токены,
рубли, `ok`, модель; у повтора `attempt: 2`), `check` (замечания кода K1–K12), `review` (Ч1–Ч8 и
`red`), `budget_skip` (круг доработки или повтор прототипа пропущен: не хватило дневного
бюджета), `time_skip` (то же, но не хватило времени прогона: шагам основного прохода впереди
оставляется половина их таймаутов),
`proto_check` (P1–P5), `accept` (`step`: `accept_code` или `accept_review`), `done` (итог) и
`failed` (`code`, `message`). После `done`/`failed` поток закрывается, а через 330 с (лимит
прогона + 30 с) — в любом случае, браузер переподключается с `Last-Event-ID`; пока ничего не
происходит — комментарий `: ping` раз в 15 с. Ответов моделей в событиях нет: разбор, ТЗ и прототип берутся из
`GET runs/{id}` по `step_end`.

```
id: 4
data: {"seq": 4, "t_ms": 9800, "type": "step_end", "step": "spec", "round": 1, "attempt": 1, "ms": 5680, "tokens_in": 1830, "tokens_out": 2410, "rub": 0.55, "ok": true, "model": "gemini/gemini-3.1-flash-lite"}
```

Прототип отдаётся с `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; …` (сети
нет) и `Vary: Sec-Fetch-Dest`, страница встраивает его `<iframe sandbox="allow-scripts">` без
`allow-same-origin`. Отдельной страницей он не открывается: свой адрес рамка сменить может (CSP
этого не запрещает), поэтому страница демо ставит `frame-src 'self'`. Прототип с ошибкой P3 (сеть)
не хранится и не отдаётся: `prototype.url` = `null`, приёмка — «прототипа нет».

Деньги: худший случай основного прохода резервируется целиком при старте прогона и расходуется
шаг за шагом, поэтому второй прогон, круги доработки и повтор прототипа берут только то, что
сверх него.

Ошибки — `{"code", "message"}`: `bad_request` (422), `too_long` (413), `rate_limited` и `busy`
(429, с `retry_after_s`), `budget_exhausted` и `offline` (503), `not_found` (404). Прогон, который
упал, — `status: "failed"` и `error.code`: `model_format` (модель дважды ответила не по схеме),
`model_error` (шлюз не ответил), `timeout` (дольше 300 с), `budget_exhausted`, `restart` (сервис
перезапустился посреди прогона), `internal`.

Все ответы `Cache-Control: no-store`, кроме examples (`public, max-age=300`).
