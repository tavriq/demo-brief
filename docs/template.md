# Шаблон ТЗ

Черновик 08.10, автор правит по опыту аналитика. Модель пишет ТЗ в JSON по схеме `app/schema.py` (`SPEC`), код собирает из него текст в этом порядке.

| # | Раздел | Что внутри | Поле схемы |
|---|---|---|---|
| 1 | Цель | что изменится для бизнеса и по какой цифре поймём, что получилось | `goal.text`, `goal.metric` |
| 2 | Роли | кто работает в системе и что делает; «пользователь» без уточнения не годится | `roles[]` R1.. |
| 3 | Сценарии | у каждого — одна роль, шаги действиями человека и результат | `scenarios[]` S1.. |
| 4 | Данные | сущности, их поля и откуда они берутся (кто вводит, откуда приходят) | `data[]` |
| 5 | Интеграции | внешняя система, зачем, направление обмена, что делаем, если она недоступна | `integrations[]` |
| 6 | Нефункциональные требования | скорость, нагрузка, доступность, данные, всё с числом | `nfr[]` N1.. |
| 7 | Критерии приёмки | проверяемые «да / нет» без автора ТЗ; у каждого сценария хотя бы один | `acceptance[]` A1.. |
| 8 | Риски | что может пойти не так и что делаем | `risks[]` |
| 9 | Оценка | части работы в днях и сумма | `estimate` |
| 10 | Допущения и вопросы клиенту | что додумали сами и что спросить до старта | `assumptions[]`, `questions[]` |

Как критерий приёмки проверяется (`acceptance[].check`):
- `screen` — у сценария `target` есть экран в прототипе. Проверяет код.
- `field` — в прототипе есть поле `target` («Запись.телефон»). Проверяет код.
- `review` — остальное, решает модель-ревьюер по ТЗ и тексту прототипа.

Объём для демо: 2–4 роли, 3–6 сценариев, 4–10 критериев. Оценка — для одного разработчика с ИИ-агентами, в рабочих днях.
